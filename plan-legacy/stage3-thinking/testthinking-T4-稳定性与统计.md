## 一、先把"稳定"拆成五个可测的量

Owner 原话是"输入任意小游戏都能稳定产出结果"（规划:11）。这句话里至少藏着五个不同的量，混在一起统计必然得出无法复算的数字：

1. **会不会做出来**（L 级条件通过率 P(L1|L0)）——产品能力；
2. **每次都做出来吗**（同输入跨轮判定翻转率）——过程稳定性；
3. **每次做出来的东西一样吗**（产物摘要唯一值数/N）——字节/结构确定性；
4. **判定器自己稳不稳**（同输入、同判官重复跑的自一致）——量具稳定性；
5. **做不出来时能不能定位到人**（可诊断率）——可维护性。

规划 §2.3（:45）已把 2/3/5 写成"四量"，并规定"尾部 = min over rounds"作为对外承诺，但没有把 **4 单列**。把量具的波动混进产品失败的分母，是这套产线历史上已经踩过的最大的坑——见第三节实测。

## 三、三个硬发现（本次实跑，改变了设计优先级）

**发现 1：红路是"环境条件性"的，好输入与坏输入在退出码上不可区分。**
契约写在 `qacore/src/run.ts:82-90` 与 `qacore/cli.mjs:10-11`（0 绿 / 1 红 / 2 用法错）。实跑：

```
node qacore/cli.mjs run /tmp/definitely-missing.html
  → exit=1  stderr: Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'playwright'
            imported from ...\qacore\src\run.ts
node pf/pf.mjs validate specs-eval/bad/01-missing-field.json
  → exit=1  stderr: ... Cannot find package 'ajv' imported from ...\packages\spec\src\validate.ts
node pf/pf.mjs validate specs-eval/golden-match3.json
  → exit=1  （同一错误）        ← 好输入与坏输入同为 exit 1
node pf/pf.mjs bogus
  → exit=2  stderr: pf: 未知子命令 'bogus'      ← 唯一仍正确的通道
node packages/assetkit/selftest.mjs → exit=1，stdout 空，stderr 首行 ERR_MODULE_NOT_FOUND
node webui/selftest.mjs             → exit=1，断言失败"服务 /api/health 60s 内未就绪"，耗时 60.3s
```

根因：`qacore/cli.mjs:15` 静态 import `run.ts`，而 `run.ts:14` 顶层 import playwright——**参数解析发生在模块图加载之后**。环境一坏，exit 2 通道整体消失，所有路径退化成 exit 1。

对统计的后果是致命的：批跑器若按"exit≠0 = 产品失败"计分，会把应当被拒的坏输入和应当通过的好输入**记成同一种失败**；分桶成功率、可诊断率、F1–F8 归因全部被**系统性**偏污染，且越依赖浏览器的桶污染越重——恰好是最该被测的桶。

三条设计结论：(a) 批跑结果类型必须是**四态**（PASS / FAIL / ENV_ERROR / USAGE_ERROR），ENV_ERROR 不计分子也不计分母，但整轮标黄且禁止据此放行；(b) CLI 参数解析必须与重依赖 import 解耦（懒加载），使 exit 2 在任何环境下可达——M0 的可测试项就是上面这两条命令；(c) ENV_ERROR 靠**签名匹配**识别（ERR_MODULE_NOT_FOUND / ENOENT / 浏览器可执行文件缺失 / 端口占用），并有反测试：故意注入一个 ENV 错误，断言它被归 ENV 而不是 FAIL。

**发现 2：判官自扰会伪装成 90% 的产品失败率。**
`docs/diff/differential-report.md:90`（QC-02）：D-1 首轮 `qacore_N(A) ≢ qacore_O(A)` **43/48 格不等**，全部是 CHK04；根因是 `run.ts` 的 `wire()` 以 `void` 火忘武装拦截，`page.goto` 与 `routeWebSocket` 竞速，AudioContext 以 running 态创建——**判官自扰，不是产物缺陷**（修法仍在 `run.ts:195` 附近的注释里）。这是仓内留档中最大的一次"假失败潮"。

由此得稳定性测试第一原则：**先证明量具是稳的，再测被测物。** 落成一条每轮批跑之前的前置门（失败则整轮作废，不记为桶失败）：
- **金丝雀**：已知全绿夹具 `qacore/tests/fixtures/mini.html` 连跑 3 次，逐 CHK status 三次全等且无 skip；
- **带负载金丝雀**：同一夹具在批跑并发度 jobs 下再跑 3 次。必须有——`e2e-matrix.mjs:16-20` 的宿主注记明写 jobs=4 时 4 路 chromium 把冻结的 CHK09（2.0s）顶破（load_ms 3.4–8.4s），并给出"单格 canary 777ms 证明非产物缺陷"的判别法。**jobs 是协变量不是常量**：跨轮比较只在 jobs 相同时有效，round 元数据必须记 jobs / 机器负载 / chromium 版本；
- 金丝雀绿而某桶红 → 桶失败可信；金丝雀红 → 整轮判 ENV/APPARATUS，不得据此改产品。

**发现 3：字节确定性的现有证据只有一格，不是 48 格。**
`docs/diff/differential-report.json:16` 写的是"字节全等格 0/48"——那是**跨实现**（oracle vs factory）字节全等率；`differential-report.md:20` 的"实现内两次构建字节一致"证据是 **tiktok zip 一格**（PKG-03 行 :88 同指该格）。规划 §5.3（:130）把"48 格两构建字节全等 0/48"列为 M1 待修的三随机源，但这两个量不是同一个，现有 A 级留档**不足以支撑 48 格实现内确定性的断言**。我 grep 了构建路径：`packages/templates/*/build.mjs`（4 个）与 `packages/packager/bin.mjs` 中 `Date.now|new Date|Math.random` **零命中**；全仓命中集中在报告/编排层（`packages/assetkit/src/pipeline.ts:142`、`pf/src/make-cmd.ts:336`、各 diff 脚本的 `capturedAt`）。推论：M1 更可能要修的是**摘要口径**而不是"构建随机源"——先定义摘要范围，再谈修。

## 四、分桶与采样：试验单位是输入，不是试次

**桶的定义**沿用规划（输入形态 × 机制族 × 渠道），补两条纪律：

- **渠道必须单列**，理由是实测的数：渠道 `maxBytes` 只有 5,242,880 与 3,145,728 两档，而 `maxFiles` 从 1（preview/applovin/meta 单 HTML）到 100（mintegral/tiktok）再到 512（google/unity zip）——**跨两个数量级**（`channel-rules/channel-rules.json` 实读）。同一产物在 preview 是"单文件全内联"，在 google 是"zip 目录结构 + 入口名 + 文件数"，合并统计等于把两种问题塞进同一个分母。
- **承诺桶 vs 观测桶必须分开注册。** 26 家族 × 4 形态 × 7 渠道最多 728 桶；对每桶都做 95% 检验，族系误差率 = 1 − 0.95^728 ≈ 1，什么都证不出来。正确做法：只有 owner 冻结过的少数**承诺桶**（规划 §2.3 的 T1 L2≥95% / T3 L1≥70% & L2≥30% / T-mid L2≥60%）带下界承诺，其余全是**观测桶**——只报计数、翻转率、F 类分布，不出区间。观测桶晋级承诺桶的流程要写死（连续 K 轮样本量足够 + 责任人签字），防事后挑桶。

**试验单位与配对**：同一输入在 R 轮里出现 R 次，这 R 次**不是独立样本**（同一输入难度、同一机器、同一代码），它是**区组**。因此：

- 独立证据的单位是**输入**。桶级报告三件套：`mean(p_i)`、`min(p_i)`（最差输入）、`p_i<1 的输入占比`。**对外承诺建议改为"每轮桶内最差输入的条件通过率"**——规划现口径 `min over rounds` 只对轮次取最小、对输入是平均的，而用户遇到的是最差那个输入。
- **跨版本比较必须配对**：同一批输入、同一台机器、交错跑两个 commit，用 **exact McNemar**（只看不一致对 b/c，discordant < 25 用精确二项）判"是否让成功率下降"。不要比较两个独立比例——那会把机器负载差当成产品差。
- 轮数：承诺层 R=5（规划写 3，我建议 5：三阶统计量方差太大，多两轮边际成本约 11 小时/轮）；回归/趋势层 R=1；金丝雀 k=3。

**算力现实**：`e2e-matrix.mjs:19` 实测注记——jobs=2 时 48 格 921.8s（≈19.2s/格）；`differential-report.md:89` 的交叉质检 96 跑墙钟 791.6s。30 真实游戏 × 7 渠道 × 5 轮 = 1050 次判 ≈ 5.6 小时/轮、5 轮 ≈ 28 小时（单机器共享、jobs 固定 2）。所以日跑只跑 2 渠道 × 30 输入 × 1 轮（≈9.5 分钟，进日常门禁），周跑 4 协议类代表，release 才 7 渠道。**砍渠道维度、不砍轮次**这条规划纪律是对的，但"哪一档跑几轮"必须进 round 元数据，否则跨档数字不可比。

## 五、显著性：三个问题必须用三把不同的尺子

稳定性测试里混用 p 值和置信下界是最常见的错误。

**问题 1「能不能对外承诺 ≥X%」——用单侧精确下界，不用 p 值。**
Clopper–Pearson 单侧 95% 下界，零失败时 p_L = 0.05^(1/n)。手算（本次无 scipy，公式一行可核验）：n=59 → 0.9505；n=29 → 0.9019；n=9 → 0.7169；n=5 → 0.5493。允许失败的版本更贴近真实批跑：n=100 最多 1 失败、n=150 最多 2 失败，下界才 ≥95%（手算 P_{0.95}(X≥148|n=150)=0.0181≤0.05，而 X≥147 时 0.0547>0.05）。

由此得一条对 owner 很重要的推论：**承诺值必须显著高于实际运行点，否则永远证不出来**（观测率恰等于承诺率时，下界随 n 增大只渐近到观测率）。所以：T3 的 L1≥70% 若实际只稳定在 70%，这个承诺**不可证**，要证 70% 需实际跑到 85% 以上（n=30 时 26/30=86.7% 才够）；T3 L2≥30% 在 n=30 时需实测 14/30≈46.7%；T1 L2≥95% 在 30 输入 × 5 轮 = 150 试次下最多容忍 2 次失败——**"95%"的真实含义是"150 次里最多坏 2 次"，应原样写进对 owner 的说明**。

建议门禁取两把尺子中**更严者**（CP 单侧 95% 与 Wilson 单侧 95%）。Wilson 在 n=20 全成功时双侧 95% 下界仅 0.839（中心 0.9194、半宽 0.0806），n=59 时双侧也只有 0.939——小样本友好不等于小样本可承诺。Wilson 适合**报告给人看**的区间，CP 适合**设门**。

**问题 2「这次改动让成功率降了吗」——配对 exact McNemar。** 配对设计下功效远高于比较两个独立比例；不显著时不要写"无回归"，写"证据不足（discordant=0/2，n=多少）"。

**问题 3「这个格稳定吗」——零翻转的等价样本量与零失败相同。** n 次试验 0 翻转时，flip rate 的单侧 95% 上界同样是 1 − 0.05^(1/n)，n=59 时 <5%。这是个很干净的对称：**想同时说"成功率高"和"判定稳定"，证据成本一样，都是 59 次无例外试验。** 现有 d2 `--det-cells` 只做 N=2，N=2 时 0 翻转只给出上界 0.776——几乎什么都没证明。所以"96 跑全等"不是稳定性数据：它是 48 格各 1 次的**跨判官**比较，不是重复性。

**样本量不足的桶必须显式标"样本不足"**：n<5 时下界没有信息量（n=1 全成功，CP 下界=0.05），只报计数。30 款基准覆盖 21 家族，注定了**多数家族桶 n≤2**——所以 T1 的承诺只能在"输入形态"层做，家族只做观测桶。这不是保守，是数学。

## 六、回归与漂移：三层摘要 + 一张 volatile 字段黑名单

| 层 | 摘要对象 | 期望 | 漂移了说明 |
|---|---|---|---|
| L-字节 | 产物文件 sha256 | R 次全等 | 构建有随机源 / 未播种 RNG / 哈希序遍历 |
| L-结构 | 规范化摘要（去 volatile） | R 次全等 | 构建不稳，但产物仍合规 |
| L-行为 | 行为流折叠摘要（d4 四条） | 胜负必等 + 手势 ±1 | 玩法语义漂移 |

**volatile 黑名单**（从代码逐个读出来，报告层天然含时钟，规范化必须剥掉）：`e2e-matrix.mjs:374` 的 `generatedAt`、各 diff 脚本的 `capturedAt`、summary 的 `wallSec` 与 `cells[].wallSec`（:303）、qacore 报告的 `facts.load_ms` / `pf.readyMs` / `pf.endMs`（`run.ts:337-390`）、`viewport_shots.*.variance` 浮点、截图 PNG。**规范化摘要 = 剥这些字段 → 排序序列化 → sha256**。有了它，"评测输出可复跑"才字面成立——顺带一提，任务书里"评测输出无时间戳"在现仓其实不成立（summary 与 evidence 都写了时间戳），所以**必须规范化，不能依赖"本来就没有时间戳"这个假设**。

**漂移预算**逐层给，且每条配动作：L-字节 0（漂移即红，且第一次漂移要先怀疑摘要范围定义错了，而不是"还有一个没找到的随机源"）；L-结构 0（同一 commit 同输入）；L-行为沿用 d4 四条；包体沿用差分报告已用的 ±5%（`differential-report.json:16`）但**只报警不设门**——包体是内容的结果，不是缺陷的证据。

**留档纪律**（基线 §六.1/§六.6 两次事故）：漂移台账**只追加**，目录进 `.gitignore` 白名单。工厂现仓 `.gitignore` 第 1–5 行排除 `node_modules/ artifacts/ tmp/ *.log`——`artifacts/matrix/summary.json` 与 `tmp/diff/*.json` **都不入库**，这正是基线记的"6 处 A 级主张永久停在 B"的根因（`differential-report.md:86` 那行证据路径 `tmp/diff/d1-packages-evidence.json` 就是悬空的）。新仓第一天要把 `runs/<date>-<commit>/` 放进白名单并禁止复跑覆盖。台账要机生：每轮追加一条 NDJSON（commit、round、jobs、chromium、桶、三态计数、F 类分布、各层摘要），"当前状态"是查询出来的——基线通则"台账一律 B"就是为手维护台账写的。

**一个容易漏的回归项**：`.gitattributes:5` 的 `* -text`（注释明写为保住与 oracle 逐字节一致的数据资产、抵消全局 `core.autocrlf=true`）。删掉它或在别的平台 checkout，字节摘要会静默变化。**要有一条测试断言它存在**——最便宜的一条回归门。

## 七、fuzz / 坏输入：五层，且必须测性质而不是用例

1. **CLI 层**：未知子命令/旗标、缺值、多位置参数、数值解析失败 → exit 2。今天这条实测是绿的（`node pf/pf.mjs bogus` → exit 2），但它绿只是因为没触发懒加载路径。CI 必须跑两轮："环境完好"与"环境故意损坏（临时改名 node_modules）"，两轮都要 exit 2。
2. **类型层**：不存在、非 .html（现状）、zip（现状 exit 2，`run.ts:86-90`；M1 要收 zip，这是行为变更，**变更本身要有测试**）、目录、软链、APK（v1 明确拒收 exit 2 + 诊断）。
3. **结构层**：畸形 spec。现仓有两层分责的现成范式——`packages/spec/test/schema.test.mjs:35-47` 断言 bad/01/03/05/06 必被 **schema 层**拦、bad/02/04 必被**不变式层**拦，且断言 02/04 在 schema 层**必须放行**（防两层职责混淆）。"哪个层拦的"比"拦没拦"更有断言价值。
4. **资源层**：超大输入（须早于加载拒）、深嵌套 JSON、重复键、尾随垃圾、BOM/CRLF/NUL/非 UTF-8、zip-slip、zip bomb、10k 文件包。每条都要有上界与超时断言，且超时必须是 F7 TIMEOUT **第三态、不得并入 fail**（规划:182）。
5. **语义层（非游戏输入）**：非游戏文本（"帮我写辞职信"）、非游戏 HTML（登录页/404/博客）、APK、纯视频。判据不是"拒了"，而是三条同时成立：①被拒；②诊断指到具体缺口（分类学 NEW 逃逸口，不是"不支持"）；③同一坏输入重复 R 次诊断**完全一致**（做不到就说明理解层有 LLM 随机性，红路不可回归）。反向约束：基准集任何一款不得被语义层误拒——**误拒只报不设门**（设门会诱发开发去调坏输入构成，坏输入集随即失真；规划:186 已裁定我同意，且测试里要显式写成"只统计不断言"的报告项）。

**fuzz 应该是性质测试**：种子取 golden spec，变异算子固定清单（删必填 / 类型互换 / 枚举注入 / 边界 ±1 / 深嵌套 / 重复键 / 尾随垃圾 / 超长串 / 数字溢出 / 负数），固定随机源保证可复跑。对每个变异产物断言一个二择一性质：

> 要么被某个**已注册的**层以**已注册的**错误码拒绝；要么被完全接受并跑完整条下游链路。**不允许第三态**（崩溃、挂起、写到一半的产物、静默接受）。

配套两条：(a) **崩溃自由**——无未捕获异常，无非 0/1/2 退出码；(b) **半写产物禁令**——被拒输入的输出目录必须为空或只有诊断文件，任何产物残留即红。半写产物是 fail-closed 最常见的破口：拒了但已写 index.html，下游会捡走它。

**变异覆盖门与稳定性门的关系要写清**：规划 §2.1（:35）要求无恰命中变异样本的 CHK 标"未证明有效"不计入 L1。同理，**这样的 CHK 也不能计入 L1 的分子**，否则恒绿检查项会稀释成功率统计。现成恰命中样本只有 MUT-01/02/04（`mutations.mjs:32-48`），而 **MUT-03（结束页不可达）在注释 :14 里就写着"仍列 M8 全量里程碑"**——即 CHK07 的"结束页不可达"这一支今天没有任何恰命中样本。M1 要补的第一批变异样本应从这里开始，因为假可玩家族缺的正是它。

## 八、失败分类学与可诊断性

规划给了 F1–F8（:184）。基于本次读码与实跑提**两条增补**（提案，非已决）：

- **F0 ENV / APPARATUS**：判官或环境自身不可用（缺浏览器、缺模块、OOM、端口占用、机器过载）。证据即第三节实跑：今天好输入与坏输入同为 exit 1。**没有这一类，ENV 失败会被记成 F3 BUILD_FAILED 或 F4 COMPLIANT_FAIL**，可诊断率的分母被污染，归因指向错误模块——这正是基线 §六.2 台账漂移的机制性来源。
- **F9 JUDGE_FLAKY**：同输入同判官两次跑判定不一致。证据是 QC-02（43/48）。特征签名：波动与**输入无关而与装置相关**，判别式就是"金丝雀是否同时翻"。必须**独立成列**，因为处置动作（修 harness，不是修产品）与 F1–F8 完全不同，混在一起会让人去改产品。

规划已有"判官无法判定"单列（:184），我只想强调它必须有**自己的分母**：既不并入 fail 也不并入 pass。否则任何"判不了"都能变成"差不多算过"，失败率这个数就不可证伪。

**可诊断率的操作定义**（规划说 ≥80%（:165）但没定义"可诊断"，这个定义必须补，否则数字可被任意解释）：

> `diagnosable(f) = (module ∈ 七块注册表) ∧ (check_id ≠ ∅ ∨ file:line ≠ ∅) ∧ (typed_outcome ∈ {PASS, FAIL, ENV, USAGE, TIMEOUT})`

七块注册表用规划 §5.2（:126）的 intake / understand / plan / synthesize / package / judge / report-regression，每块唯一责任人。**归不进任何一块的失败本身就是 report 层缺陷，必须让门禁红**——无主失败比失败更贵，它静默吃掉排查时间。所以可诊断率是**双向门**：上限（≥80%）与下限（未归因失败数必须为 0）。

**分类器本身要可测**：F 类映射必须是确定性函数（exit code + stderr 签名 + check_id + stage 标记 → F 类 + 模块），不是模型判断。配两个门：(1) **回放测试**——把历史失败语料（stderr 头 + exit + check 列表）固化成 fixture，分类器必须逐条复现当时归类；(2) **分类覆盖门**——最近 K 轮出现的每一个新 stderr 签名必须有已注册映射，新签名率为 0，否则门红。这条门专防"把新失败归进'其他'然后一直绿"。
