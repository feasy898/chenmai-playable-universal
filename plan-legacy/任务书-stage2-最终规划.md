# 任务书 stage2：最终规划文档撰写（GLM53 合并执行者）

> 版本 v1.0（2026-10-03）。你是合并裁定者：依据基线、人类意图与五份思考轨迹，撰写唯一的正式规划文档。

## 输入（全部必读）

1. 基线总文：`_baseline_inventory\项目真实能力基线总文.md`
2. 人类意图：`_playable_plan\任务书-stage1-规划思考.md` 第一节（权威，目标不得改写）
3. 五份思考轨迹（`_playable_plan\stage1-thinking\` 下全部 5 份）

## 产出

`_playable_plan\最终规划文档.md`，6000–10000 字中文。这是给后续开发 agent 执行的正式文档：**自含、可执行、可验收**——读者不需要回看五份思考也能开工。

## 必备结构

1. 目标与范围（含 owner 交付定义：输入任意小游戏稳定产出、对齐真实可玩广告）
2. 完成定义 DoD（分级判据，逐级可机检）
3. 小游戏类型全集与输入集（分类学结论 + ≥30 款真实游戏输入清单及获取形态）
4. 平台合规矩阵与服务边界（差异矩阵、公共分母、合规门设计）
5. 服务架构与管线设计（模块切分、与现有 chenmai-playable-factory 的复用/重构决策及理由）
6. oracle 比对与吸引力基准（oracle 样本库建设方案、比对方法、吸引力指标）
7. 里程碑与门禁（M0/M1/…，每步有可验证出口与量化放行条件）
8. 测试与质量策略（策略级；详细测试文档由 stage4 另出）
9. 风险与开放问题（含需 owner 拍板项）
10. 附录：五份思考的关键分歧与裁定记录（谁主张什么、你采信什么、为什么）

## 裁定纪律

- 五份思考中的分歧你有权裁定：**不得和稀泥**，重要分歧逐条给裁定与理由（附录留痕）；
- 基线事实优先：不与已验证能力/已知红线冲突，引用基线条目编号；
- 诚实纪律：规划里每个承诺必须可验证（有门禁/有数字/有判据）；不确定的标开放问题，不许写成已决；
- 平台规格、广告行业数字若来自代理的网络研究，注明「来源：思考文档 MM-A/B（含 URL）」，未经你独立复核的标注置信度。
