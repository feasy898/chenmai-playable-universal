## 0. 我研究了什么（先亮证据底账）

**仓内实读（全部亲自打开核对）**：

- `chenmai-playable-factory/package.json` + `README.md`：管线 = 校验 → assetkit 素材优化 → 模板构建（单 HTML）→ 渠道打包 → qacore 判官 `--autoplay` 试玩质检 → 汇总页 + 二维码 + demo-prebuilt 兜底；质检不过 make exit 1、不产二维码（"宁可失败不可假绿"）。
- `packages/spec/playable-spec.schema.json`（第 45–100 行实读）：`game.template` 是**封闭枚举** `["match3","merge","pullpin","sort"]`，`additionalProperties:false`，params 按 if/then 挂四套子 schema。specVersion 钉 1.0.0、"数据契约零变更"是仓纪律。但 spec.md §2 差异4 登记了 `registerTemplateCheck` 注册制接缝——不变式检查可扩展，**schema 枚举本身仍是硬边界**。
- `docs/specs/qacore.md` §5.1/§6：判官十项检查 CHK01–10，其中 **CHK02（文件数）、CHK06（退出接口）skip 未实装**；CHK07 依赖被测物自己实现 `__PF_QC__` 钩子（hint/state/endScreenVisible/texts/textStates/assets）——**质检契约是模板协作式的，判官的"自动试玩"靠被测物上交真实最优下一步坐标**。
- `channel-rules/channel-rules.json`：七渠道 = preview（本地质检渠道）+ applovin/meta/mintegral/google/unity/tiktok 六投放渠道；多条 source 字段自注"D9 官方工具实测后回填"——**平台合规线是行业基线+内部从严，未经官方工具验证**。
- `packages/llmgw/`：**只有一个 package.json，无 src**——README"预留/未做"栏自认 director（AI 生成）未开工。全产线目前零 LLM 生产调用。
- demo-zh spec 里的 `attract:{nearWin,failBait,firstClickSucceed}`、`difficulty.targetLevel`、`durationBudgetSec:{target:20,max:30}`、`flow.tutorial.maxSec:4`——**v1 作者已经把"吸引人"参数化了**，这是 L3 分级的宝贵种子。
- 基线总文 §3.1：差分终审 48 包零回归 A 级；「任意小游戏→稳定产出」远超模板法能力。

**web 检索（行业事实，附来源）**：

- 交互时长 15–30s、约 20s 最佳（[Segwise playable ads guide](https://segwise.ai)）；hook 3–5 秒内抓住注意力、教学单手势不靠阅读、CTA 放在胜利/高潮时刻（[AppAgent](https://appagent.com) 等多方综合，属行业共识而非单一权威数字）。
- 转化基准：playable 平均安装率 5.8% vs 展示广告 1.2%（[AppSamurai](https://appsamurai.com)）；impressions-to-install 8–16 倍（[Mistplay](https://business.mistplay.com)）。
- 技术规格：多数网络 ~2MB 标准、AppLovin/Unity 5MB 上限（[defold-playable-ads](https://github.com/indiesoftby/defold-playable-ads)、[construct.net](https://www.construct.net)）；Meta 要求单 HTML 全 data-URI 内联（[Tumult 论坛引官方 spec](https://forums.tumult.com)）；Google 要求用户交互前不出声（[Google Ads Help](https://support.google.com/google-ads/answer/9981650)）。
- 「convert any game to playable ad」检索结论：**没有成熟的通用自动转换商品**，市场形态是自由职业者手工服务 + 引擎导出 SDK（Upwork 检索结果佐证）。这印证「任意游戏」是未解决难题，不是买个工具的事。
- 诚实声明：**「DoD 质量分级」不是行业标准术语**，检索无果；分级框架是本任务自建的内部队列，对标物是各平台离散的合规清单 + 最佳实践文。

## 1. 核心张力：现在的"完成"与 owner 要的"完成"差在哪

现状的完成定义是**隐式**的：make exit 0 = qacore 十项无 fail + 48 包矩阵零回归。它对 4 模板极其扎实（A 级），但它是**产物级**的 DoD，不是**服务级**的。owner 的第 8 条要的是：「输入任意小游戏都能稳定产出结果，结果对齐真实的可玩广告」——这里"完成"的主语从**产物**变成了**服务**。

【推断】差距的本质：模板法把「游戏理解」这一步外包给了人——是人看了一款游戏后决定"这是三消、填 match3 模板"。产线从未做过理解，只做过参数化。所以升级不是"加模板"，而是要在产线头部**长出一个此前不存在的认知层**。这个判断决定了我后面所有架构权衡的走向。

## 2. DoD 分级建议：L0–L3 阶梯 + F 对齐轴

任务书提示了 L0 构建→L1 可玩→L2 可投→L3 吸引人。我细化判据时发现一个必须先回答的结构问题：**"对齐"有两个不同的方向**——(a) 对齐输入游戏（保真：做的是"这款游戏"的广告）；(b) 对齐真实在投 playable（质量：达到广告工业水准）。L0–L3 阶梯只能表达 (b)，(a) 若混进阶梯会互相污染（一款保真度满分但平庸的产物，和一款面目全非但精彩的产物，都不是 owner 要的）。所以我建议**两条正交轴**：

### 2.1 交付质量阶梯（L 轴）

**L0 构建级**：make exit 0；单 HTML 自包含零外链（CHK03）；包体 ≤ 渠道上限（CHK01）；本地加载 ≤ maxLoadSec（CHK09）；控制台零错误（CHK08）；横竖屏双仿真非空白（CHK05）。全部今天就能机检，qacore 现成。

**L1 可玩级**：真实交互 + 真实胜负判定。判据：
- 输入依赖性【关键新增】：**提示策略胜率必须显著高于随机策略胜率**（各 N 轮 autoplay）。随机乱点也能"赢"的产物 = 假可玩（ canned 动画冒充游戏），必须拦。这直接复用现有 autoplay 基建，只需加一个随机手势策略档。现有 CHK07 只证明"照着提示能到结束页"，证明不了"不照提示到不了"——这是当前判官的盲区，我读 qacore.md §5 时确认的。
- 事件流完整：pf:ready → pf:start → pf:first-interaction → pf:end(win) 时序合理、手势数 ≥ 下限、结束页可见。
- 实现方式上要求 LLM 合成物同样挂 `__PF_QC__` 契约（钩子契约从"模板义务"升格为"一切产物义务"）。

**L2 可投级**：平台合规全过。七渠道包全部过规则库 + 补齐 CHK02/CHK06（现状 skip，skip 不算过的纪律必须坚持）+ 静音/退出接口/zip 结构逐渠道断言 + 健壮性（低端机仿真、加载预算）。【待验证】渠道真实审核只有 D9 官方工具回填后才能闭环——本地 L2 是"可投的必要条件"，不是充分条件，这点要在 DoD 文档里写死，防止自我麻痹。

**L3 吸引人级**：对标真实广告。硬代理指标（可机检）：首含义交互 ≤5s（从 load 到 pf:first-interaction，正对齐行业 hook 3–5s 共识）；教学单手势 ≤4s（spec 已有 tutorial.maxSec，升格为判据而非参数）；交互总时长落 15–30s 窗（durationBudgetSec 从参数变成被裁决的合同）；CTA 只在 end/win 之后出现且形式正确；`attract.firstClickSucceed` 类剧本真实生效。软判据（VLM/LLM 盲评 + 人眼抽检）：与 oracle 样本库的体验比对、end card 质量。**L3 的锚必须是 oracle 库**（视角4的职责），否则"吸引人"会退化为自说自话。

### 2.2 输入对齐轴（F 轴）

F0 声明对齐（GameProfile 声称实现了输入游戏的核心机制，可结构比对）；F1 行为对齐（事件流/操作-反馈模式与源游戏可比对——源是 HTML5 时甚至可跑双录对比）；F2 体验对齐（视觉风格/手感，VLM 盲评）。L 与 F 独立报告，**服务级 DoD = L2×F1 起步、目标 L3×F2**。

### 2.3 分级的三条设计纪律（继承产线文化）

1. 条件式裁定：上级裁定前先过下级（L1 不过不谈 L2），失败定位到级。
2. skip ≠ pass（qacore 现有纪律直接沿用）。
3. 分级必须全部可自动化——人眼只允许出现在 L3 抽检位，否则"稳定产出"无法回归测试。

## 3. 输入形态研究：服务边界划在哪

| 形态 | 信息保真上限 | 主要难点 | v1 建议 |
|---|---|---|---|
| T1 HTML5 源码/zip | 最高（机制+素材+参数全可提取） | 任意代码：需静态分析+沙箱动态插桩识别机制（Phaser/Construct/Cocos/自研）；引擎指纹 | **v1 主通道**，benchmark 主体 |
| T2 试玩页 URL | 同 T1（可无头抓包抓 DOM） | 反爬/混淆/资源跨域 | v1 作为 T1 的采集器子形态 |
| T3 玩法文字描述 | 最低（机制靠人描述，视觉全靠生成） | 保真不可验证；幻觉风险最大 | v1 支持（owner 明示"次级是自己写一个"，正落在此档），F 轴只要求 F0 |
| T4 截图/视频 | 中（视觉风格+外观机制，动态靠猜） | 视频交互反推机制是无解问题，只能合理重建 | v1.5 再开 |
| T5 APK | 理论高实际极低（反编译 il2cpp/混淆，工程黑洞） | 见 GPU 训练机教训类的投入产出陷阱 | **v1 明确拒收**：优雅 exit 2 + 诊断信息（红路测试的一部分） |

【推断】服务边界诚实声明是 DoD 的一部分：「任意小游戏」数学上不可穷尽，服务承诺应该表述为"覆盖已版本化机制分类学（视角1产出）的输入，分类学外输入明确拒收并给出缺口报告"，而不是无限的"任意"。这不是退缩，是把"任意"工程化成可管理的版本承诺。

## 4. 服务形态与架构：扩展还是重构

先摆我读出的关键结构事实：factory 是**沙漏型**——上半身（spec schema 封闭枚举 + 4 模板 + specgen 表单）是游戏相关的；腰部（`__PF_QC__` 质检契约、pipeline-contract 退出码/报告字段）是中性的；下半身（packager + channel-rules + assetkit 素材管线 + qacore 判官本体）**本质游戏无关**，且是全仓最值钱的 A 级资产（差分零回归那 48 包就是它们撑起来的）。

三个方案：

**A. 原地扩展**：加模板、扩枚举。利：零迁移成本。弊：覆盖率随手写模板线性增长，永远到不了"任意"；schema 每加一族就动一次冻结契约，违背"数据契约零变更"纪律；LLM 认知层在模板架构里没有位置。——**基本否决**。

**B. 全新重构**：新认知层 + 通用合成器（组件运行时 + LLM 代码生成），下游重写。利：无历史包袱。弊：丢掉 A 级下半身 = 丢掉全部已验证的合规与质检能力，重走一遍 48 包回归——**不可接受**。

**C. 沙漏改良（我的倾向）**：**上半身换血、腰部加宽、下半身原样复用**。具体：
- 头部新增三模块：intake（输入适配）→ understand（静态分析+沙箱插桩+VLM → **GameProfile v2**：机制类型、输入模型、胜负规则、素材、风格）→ plan（广告剧本：hook/教学/循环/CTA 时序预算，产物仍是对下游的 spec 形态）。
- 合成层：**组件引擎 + 机制族模板（升级现有 4 模板为首批机制族）+ LLM 自由代码生成兜底**。机制族命中走参数化（确定性高），未命中走 LLM 生成（覆盖广但方差大）——两条腿都要，比例随里程碑移动。
- 腰部加宽：`__PF_QC__` 契约从模板义务升格为产物义务 + 新增随机策略对照检查（L1 反假可玩）+ 时序预算检查（L3 硬代理）。
- 下半身：qacore/packager/assetkit/channel-rules 以库方式被新线调用。

**新仓还是厂内加包**？我倾向**新起 sibling 仓**（如 universal 线），factory 冻结为回归 oracle。决定性理由：factory 是终审通过的成品仓，其价值正在于稳定；而且这个项目群的方法论就是**差分链**（playable-ads oracle → factory 模式 M 差分对齐）。新线对 factory 做差分（同输入下 4 机制族的产物行为流等价性），等于把这套已被证明的文化延续到第三代：ads → factory → v2。代价是跨仓复用要走 npm file 依赖/subtree——无发布环节的私有仓，成本可控。反方观点（workspaces 内零摩擦复用、避免双仓漂移）也成立，这是我最不确定的一点，列开放问题。

模块切分定稿建议七块：intake / understand / plan / synthesize / package（复用）/ judge（复用+扩展）/ report-regression（分级报告+差分门禁）。每块沿用"spec+eval 双交付"资产纪律。

## 5. 稳定性怎么定义与度量

「稳定」必须操作化，否则无法回归。四个度量：

1. **条件通过率**：按 输入形态×机制族 分桶，报告 P(L0)、P(L1|L0)、P(L2|L1)、P(L3|L2)。漏斗式条件概率能精确定位哪一级漏水——比一个总成功率诊断价值高得多。
2. **方差一致率**：同一输入 N=5 轮（LLM 非确定性），报告分级一致率（目标 ≥0.8）、包体大小方差、时长方差。随机策略 vs 提示策略胜率差也是方差监测项。
3. **失败可诊断性**：失败分类学 E-intake / E-understand / E-synth / E-qc-hard / E-qc-soft / E-appeal，每次 exit 1 携带 {stage, class, evidence} 结构化 JSON（沿用 0/1/2 退出码契约精神）。**不可诊断的失败 = 未处理的失败**。
4. **回归门禁**：benchmark 全集（≥30 款）= 每次变更的 48 包矩阵等价物；零回归线 + 分级只升不降（降级需显式豁免登记）。

建议目标数（供 owner 调）：M2 出口 L2 ≥80%（T1 桶 ≥90%）；M3 出口 L3 ≥60%；最终 T1 桶 L2 ≥95%、混合输入 L2 ≥80%。数字本身是拍脑袋起点，但**结构**（分桶、条件、方差、分类学）是我确信的部分。

## 6. 里程碑切分（每步可验证出口）

- **M0 契约冻结**：DoD v1.0（本文 §2 细化后定稿）+ GameProfile v2 schema 草案 + 机制分类学 v1（视角1）+ oracle 库 ≥20 条（视角4）+ benchmark 输入集 ≥30 款。出口：五件资产过评审、新判据（随机策略对照）spec 冻结。**这一步全是纸面工作，但它锁定一切后续——DoD 晚定一天，返工翻倍。**
- **M1 认知层打通（限 4 已知机制族 + T1 输入）**：HTML5 源码 → GameProfile → 命中现有 4 机制族 → 复用模板合成。出口：≥10 款真实 HTML5 小游戏 ≥8 款达 L2×F1；对 factory 同机制族差分门禁绿。
- **M2 通用合成**：组件引擎 + LLM 生成腿，机制族 ≥8，T3 文字输入通路。出口：30 款 benchmark L2 ≥80%，N=5 一致率 ≥0.8。
- **M3 吸引力层**：oracle 事件流/时序对标 + VLM 盲评 + endcard。出口：盲评 L3 ≥60%，holdout 首启。
- **M4 稳定收口**：红路拒收、无人值守批跑、D9 平台官方工具回填、全量回归。出口：连续 3 轮批跑达标 + holdout 验收报告。

M1 故意做小做实——它单独就有演示价值（HTML5 小游戏自动变可玩广告），且强制认知层在合成层自由化之前先被验证。

## 7. 坑、不确定性与开放问题

坑：① `__PF_QC__` 协作式契约可被作弊实现（hint 返回真坐标但游戏不依赖它）——随机策略对照是解毒剂，必须进 L1；② autoplay 45s 预算 vs durationBudget max 30s 不一致（CONTRACTS 痛点 7 遗留）定 DoD 时会撞上，需顺手裁决；③ Mintegral build.js 空占位的审核风险（仓内已登记）；④ LLM 生成代码要在沙箱跑（安全+超时+资源上限），失败即 E-synth 分类；⑤ spec v1 的 bad/golden 资产可迁移但 schema v2 不兼容，迁移成本别低估。

开放问题（需 owner 拍板）：① APK 输入是否永久排除（我建议 v1 排除）；② 新仓 vs 厂内（我倾向新仓，理由见 §4，但复用机制需认可）；③ L3 是否保留人眼终审位（现产线 demo-checklist 有人眼复核先例）；④ LLM 供应通道与成本预算（llmgw 空壳，选哪家模型、批跑预算多少）；⑤ 真实游戏做 benchmark 的版权边界（研究用途、不照抄素材，需成文）。

## 8. 若由我定（一句话版）

DoD = **L0/L1/L2/L3 交付阶梯 × F0/F1/F2 对齐轴的二维矩阵，服务承诺 = 覆盖版本化分类学的输入达 L2×F1、目标 L3×F2**；架构 = **沙漏改良（上半身换认知层与通用合成、下半身 A 级资产原样复用、腰部 QC 契约升格为产物义务）**；组织 = **新起 sibling 仓、factory 冻结为差分 oracle 第三代**；路标 = **M0 契约冻结 → M1 小实认知层 → M2 通用合成 → M3 吸引力 → M4 稳定收口**，每级出口全部机检可回归。
