## 一、目标与范围

**Owner 目标（原文，不得改写）**：能够稳定地对于各种类型的小游戏，都形成真实可用的 playable ads；交付定义是「有这样一套服务出来，输入任意小游戏都能稳定产出结果，结果对齐真实的可玩广告」；以真实在投可玩广告为 oracle；广告要确实吸引人。

**工程化转述（不改目标，只改承诺方式）**：建成一条「输入 → 理解 → 合成 → 质检 → 打包 → 报告」的通用产线服务，满足：

1. 输入覆盖：接受 HTML5 源码/试玩页 URL/玩法文字描述三类输入（T1/T2/T3），T4 截图视频在 v1.5 开通，T5 APK 明确拒收（exit 2 + 诊断）。「任意小游戏」承诺为**覆盖版本化机制分类学（第 3 节）的输入**——分类学外输入明确拒收并出具缺口报告，触发分类学修订。这是把「任意」工程化为可管理版本承诺，不是缩小目标。
2. 产出质量：对齐两轴——交付质量阶梯 L（L0 构建→L1 可玩→L2 可投→L3 吸引人）与输入对齐轴 F（F0 声明→F1 行为→F2 体验）。服务级完成定义 = **L2×F1 起步，L3×F2 为目标**（第 2 节）。
3. 对齐真实：以 ≥30 条真实在投可玩广告语料（现成起点 21 条已验活，第 6 节）为 oracle，产物结构/行为/体验三层比对。
4. 稳定可证：分层条件通过率 + 尾部下界 + 方差 + 可诊断性四量口径（第 8 节），holdout 物理隔离验收。

**范围内**：小游戏（hyper-casual/casual/puzzle 机制域）→ 单机可玩广告 HTML5 产物的全自动产线及其测试体系。**范围外**：投放执行与买量优化、真实流量转化数据（投放侧，不可得，见 6.4）、midcore 重度品类（RPG/MOBA/4X——业界用交互视频/终局卡降级形态，显式声明不支持，来源：GLM-A 思考，待验证）、渠道面扩张（v1 维持现有 6 投放渠道 + preview，理由见 4.4）。

**与现状的关系**：现有产线（基线§3.1）是模板法 4 模板（match3/merge/pullpin/sort），48 包差分终审零回归（基线§四#10，A 级），但 `Template` 是封闭联合类型、QC 依赖模板自带钩子、渠道数值未经官方工具验证（D9 欠条）。「任意小游戏→稳定产出」要求在产线头部新增**认知层**（把「游戏理解」从人工收进产线）、在合成层引入**家族级底座 + LLM 生成双腿**、在判官层引入**无钩子黑盒驱动**——这是本次规划的全部跨越。

## 二、完成定义（DoD）

DoD 为 L×F 二维。三条铁纪律（继承产线文化）：**条件式裁定**（上级裁定前先过下级，失败定位到级）；**skip ≠ pass**（现有 qacore 纪律升格为门禁口径：任一级判定中 skip 占比 >10% 整批不采信）；**分级可自动化**（人眼只允许出现在 L3 抽检位，其余全部机检可回归）。

### 2.1 交付质量阶梯（L 轴，全部可机检）

| 级 | 名称 | 判据（机检点） |
|---|---|---|
| L0 | 构建级 | make exit 0；单 HTML 自包含零外链（CHK03）；包体 ≤ 渠道上限（CHK01，effectiveMaxBytes 取 min 且 override 只许收紧）；加载 ≤ maxLoadSec（CHK09）；控制台零错误（CHK08）；横竖屏双仿真非空白（CHK05）。全部现成。 |
| L1 | 可玩级 | ①事件流完整：pf:ready→pf:start→pf:first-interaction→pf:end(win) 时序合理、手势数 ≥ 下限、结束页可见；②**反假可玩双判据**：随机策略胜率必须显著低于提示策略胜率（各 N≥5 轮 autoplay，档 1 判据）**且** CHK11 帧间动态性 + 输入响应因果性通过（档 2/3 判据，同相位 ≥6 帧连采，交互后画面至少一次可测变化、同坐标两种输入画面必须不同）；③我方产物一律暴露 `__PF_QC__` 契约（钩子从模板义务升格为产物义务）；④变异覆盖：所用到的每个 CHK 至少有一个恰命中变异样本，否则该 CHK 标「未证明有效」不计入 L1。 |
| L2 | 可投级 | 七渠道包全部过规则库静态门 + **CHK02 文件数 QC 侧复核实装**（现状 skip，checks.ts:71）+ **CHK06 渠道退出接口门实装**（注入渠道 stub，点击 CTA 断言被调接口与参数=landingUrl；现状 skip，checks.ts:185）+ 静音/退出/zip 结构逐渠道断言 + qacore 支持 zip 产物（现状只收单 HTML，run.ts:83-88 对 zip exit 2）。**本地 L2 是可投的必要条件而非充分条件**：渠道真实审核结论属 D2 门（4.3），AppLovin/Meta/Mintegral/TikTok 数值未获官方原文前，L2 判定附「渠道数值置信度清单」。 |
| L3 | 吸引人级 | 硬代理（机检，锚定 oracle 分位）：首含义交互 ≤5s；教学单手势 ≤4s（tutorial.maxSec 从参数升格为判据）；交互总时长落在 oracle 同品类 [P25,P75]（durationBudgetSec 从参数变成被裁决合同）；CTA 时机与形式对齐 oracle 分布；attract 剧本真实生效（nearWin/failBait 实测改变胜率与时长）。软判据（登记不设门）：盲评抽检（6.4）。**L3 的锚是 oracle 库，不得自说自话。** |

### 2.2 输入对齐轴（F 轴）

F0 声明对齐（GameProfile 声称实现输入游戏核心机制，产物机制集合 ⊆ 抽取清单且逐项有实现证据——同时是反幻觉判据）；F1 行为对齐（事件流/操作-反馈模式与源游戏可比对，源为 HTML5 时双录对比）；F2 体验对齐（视觉风格/手感，盲评）。**T3 文字输入只主张 F0 + L1，不主张机制保真**（无 ground truth，不可验证的东西不进 DoD）。

### 2.3 稳定性的操作化（四量，第 8 节详述）

按 (输入形态 × 机制族 × 渠道) 分桶报告：条件通过率 P(L1|L0)…；**尾部 = min over rounds 的每轮成功率（对外只承诺这个）**；确定性 = 同输入 N 次构建产物内容哈希唯一值数/N；可诊断率 = 失败中能定位到 CHK 编号/文件行/失败类的比例。分层下界承诺（owner 确认后冻结）：T1 桶 L2 ≥95%、T3 桶 L1 ≥70% 且 L2 ≥30%、L-mid(T4，v1.5 后) L2 ≥60%。

### 4.2 现状与协议结构

七渠道 = preview（本地 QC）+ applovin/meta/mintegral/google/unity/tiktok 六投放渠道（channel-rules.json 1.1.0；oracle 仓同基线）。真实平台退出协议只有四类：MRAID.open（AppLovin/Unity/Mintegral 及多数 SSP）、FbPlayableAd.*（Meta）、ExitApi.exit()（Google）、window.openAppStore()（TikTok/Pangle）——**七渠道恰好协议完备**（来源：MM-A 实跑 + smoudjs/playable-scripts、cocos-pnp 仓）。故 v1 不扩渠道：缺的不是协议类，是同协议内的参数与元数据正确性。

### 4.3 公共分母：三档分层（采信 MM-A，否决「取最严子集」——最严并集使包体线失去意义且混淆失败域）

- **D0 硬红线**（跨渠道，违反即拒）：零外网请求（CHK03，全仓最成熟机检）；首交互前静音（CHK04）；控制台零错误（CHK08）；包不逃出 dist 根（resolveDistRef 快速失败）。
- **D1 渠道语义门**（按渠道查表）：包形态/入口名/zip 结构/文件数（build.mjs 已强制，CHK02 需 QC 侧复核）；大小上限（override 只许收紧）；forbidMraid 收窄扫描（保留「有意收窄+写明盲区」范式，新门照抄此体例）；**新增**：requiredMeta/externalScriptAllowlist 声明字段（承载 Google ad.size 等）、config.json schema 三层化（规则库声明→生成器映射→schema 校验）。
- **D2 官方工具回填门**（不可代码断言）：各渠道官方预览/校验工具实测。渠道规则真源升级：每条数值加 `evidence:{type:official|thirdparty|internal,url,verifiedAt}`，rules-check 拒绝「无 evidence 且超龄」条目——渠道漂移可检，这是最大系统性风险的解毒剂（M0 落地）。

### 4.4 七处差异修正（采信 MM-A，全部进 M1 改造项）

①Meta 大小收紧 3MB→2MB；②Meta CTA 双写探测（onCTAClick 优先回落 onComplete）；③Unity 形态改单 HTML（我方 Phase 0 实测+第三方双证据 vs 按指令冻结的 zip）；④TikTok config.json 按 playable_orientation 修正（D2 确认）；⑤Google exitapi.js 白名单例外（owner 批，桥保持无脚本可工作，两路并存）；⑥MRAID isViewable() 软等待（有则等，无则回落 ready）；⑦orientation 维度补 square 枚举（spec 现只有 portrait/landscape/both）；「一包一尺寸」输出契约变更挂起至 Google 官方确认（破坏 48 包差分基线，owner 拍板）。**顺序纪律：先补 CHK06 与 evidence 机制，再谈任何渠道面变化——否则是把「不知道对不对」复制七份。**

### 4.5 服务边界

输入形态：T1 源码/zip（v1 主通道）、T2 URL（T1 的采集器子形态）、T3 文字描述（F0+L1）、T4 截图/视频（v1.5）、T5 APK（v1 拒收，exit 2 + 诊断，属红路测试）。渠道边界：v1 固定 6 投放渠道 + preview。产物边界：单 HTML/双 zip 按渠道规则，全部自包含。

## 五、服务架构与管线设计

### 5.1 架构裁定（分歧焦点，附录 A1）

**裁定：采纳 GLM-B「沙漏改良」为管线骨架，采纳 GLM-A「5 家族 kernel + 薄玩法包」为合成层机制族腿的实现架构；LLM 生成腿保留但 M2 才启用。** 理由：两位代理的真分歧被表面表述掩盖——GLM-B 解决「头部」（模板法把游戏理解外包给人，认知层是 owner 第 8 条差距的本质），GLM-A 解决「中部」（四模板同构文件布局是重构证据，kernel 化使扩展成本从线性降为边际）。两者正交互补，不冲突；唯一实质分歧是 LLM 自由代码生成的时点，裁定 M2 起（M1 强制认知层先在确定性合成下被验证，避免方差源叠加）。否决「原地扩展」（schema 每加一族动一次冻结契约，违背数据契约零变更纪律）与「全新重构」（丢掉 A 级下半身 = 丢掉全部已验证合规与质检能力）。

**组织裁定：新起 sibling 仓（如 chenmai-playable-universal），factory 冻结为差分 oracle。** 理由：factory 是终审 A 级成品仓，价值正在于稳定；本项目群方法论就是差分链（playable-ads→factory 模式 M 差分，基线§四#10），新线对 factory 同 spec 做行为流差分 = 差分文化第三代。跨仓复用走 npm file/workspace 依赖（私有仓无发布环节，成本可控）。**硬前提**（基线教训 §六.1/§六.6）：新仓第一天起 .gitignore 放行门禁留档目录 + 只追加写盘，禁止复跑覆盖。

### 5.2 模块切分（七块，每块 spec+eval 双交付）

1. **intake**：输入适配（T1/T2/T3/T4 采集与预处理，T5 拒收）。2. **understand**：静态分析（引擎指纹 Phaser/Cocos/Construct/自研）+ 沙箱动态插桩 + VLM 辅助 → **GameProfile v2**（机制家族、四轴取值、输入模型、胜负规则、素材清单、风格；schema 新立，spec v1 golden/bad 资产迁移成本已登记）。3. **plan**：广告剧本（hook/教学/循环/CTA 时序预算、attract 参数、难度曲线），产物仍为下游 spec 形态。4. **synthesize**：选路器（GameProfile→kernel 命中）+ 机制族腿（5 kernel + 薄玩法包：规则参数+素材映射+胜负逻辑）+ LLM 生成腿（沙箱：超时/资源上限/禁网络，失败即 E-synth 失败类）；`Template` 封闭枚举改开放注册制（spec.md 差异 4 的 registerTemplateCheck 接缝顺延）。5. **package**：复用 packager + channel-rules（+4.3 新字段）+ assetkit。6. **judge**：qacore 复用 + 扩展（CHK02/06 实装、CHK11 新增、三档驱动、zip 支持、随机策略对照、时序预算检查）。7. **report-regression**：L×F 分级报告 + 失败分类学 + 差分门禁（vs factory）+ oracle 区间比对。

### 5.3 对现有 factory 的复用/改造清单

原样复用（以库方式被新线调用）：packager、channel-rules、assetkit、qacore 判官本体、engine-bridge 渠道契约、退出码语义（0 绿/1 红/2 用法错）。升格改造：`__PF_QC__` 从模板义务升为产物义务 + 按 kernel 分型（3.2）；autoplay 45s 预算与 durationBudget max 30s 的不一致（CONTRACTS 痛点 7 遗留）在 M0 DoD 定稿时一并裁决。新增：外来广告运行器（第 6 节，独立包，不进 factory 主线避免污染产物线边界）。修复：构建字节确定性（48 格两构建字节全等 0/48，基线§四#10 caveat——三处随机源：时间戳/未播种随机/哈希序遍历，M1 修复并重跑差分基线）。

## 六、oracle 比对与吸引力基准

### 6.1 三层 oracle（采信 MM-B 双版合流）

结构 oracle（包长什么样：形态/entry/内联率/包体分布/退出接口/CTA 形态）、行为 oracle（玩起来的事件序列）、体验 oracle（好不好玩）。**stage1 只能真正建起前两层；第三层只能建代理指标+盲评流程，拿不到转化真值**（行业转化数字在两次独立检索中一条都没拿到，来源：MM-B 双版实测记录，待验证项永不进验收门）。

### 6.2 样本库：21 条现成起点 + 三层构成

**现成起点（本次裁定纳入）**：static.zplay.cn 16 条 + lolipopmobi.com 5 条，2026-10-03 实测 21/21 HTTP 200、无鉴权、0.09–1.67MB 单 HTML（来源：MM-B 前稿，入口为 WckY/Playable-ads 仓的链接索引，仓本身无 license、push 2023-04）。已完成的静态分析（6 条下载件）：5/6 完全自包含零外链、1/6（idleGrassCutter）带 s0.2mdn.net CDN 外链——**证明我方零外链红线严于市场实况**；退出机制按平台变（appLovin 变体 mraid.open / adwords 变体 location.href）；URL 自带 game/variant/platform/locale 四元组；同款游戏 2–5 个创意变体（真实生产单位是「playable × N 创意变体」，我方 48 包只是换渠道包装非换钩子——服务设计须补变体维度）。

**库构成（M0 定 30 条，不贪多——人工标注 15–20 分钟/条，边际信息量低）**：L1 官方件 10 条（Liftoff 官方 preview + IAB MRAID 合规单元，BSD 许可，容器一致性基线）；L2 开源产线产物 8 条（cocos-pnp/defold 等按渠道导出，结构真实参照）；L3 真实在投语料 ≥12 条（从 21 条活体中按 8 个机制桶选取：消除/物理弹射/放置割草/竞速跳跃/绘画涂色刮刮/拼图旋转/社交剧情/工具伪商店页）。**分层纪律**：语料按采集日期分层（2019–2021 老素材无 MRAID 注入，不得拿 2020 素材比 2026 渠道规则）；每条元数据沿用 d4 流结构（pfEvents/gestures/finalState…）+ 外来补充（exit_api_called/pixel_activity_series/drive_mode/t_cta_est）+ 溯源组（sha256/fetched_at/license_status）。

### 6.3 比对方法与判据降级（关键结论）

**真实广告没有 `__PF_QC__` 钩子，「我方与真实广告事件流逐点等价」永远做不成**；且现有 qacore 对真实广告必然红（页面无 window.PF 即 fail）。故：①**外来广告运行器**（M0 最优先工程）：不复用 checks.ts 判定层，只复用探针族（音频/媒体/首指针）+ 新增通用探针（pointer/touch/key 时间线 + 退出接口拦截 mraid.open/FbPlayableAd.*/ExitApi.exit/openAppStore + 逐帧像素活动序列），产物 = d4 同构流 JSON；②行为判据退到**区间判据**：我方产物 t_first/t_tutorial/t_loop/t_cta 落同品类真实广告 [P25,P75] 为达标，超 P90 或首屏 10s 零交互判 fail（红路），区间外偏离登记不判 fail；t_cta/t_loop 用像素活动序列估阶段边界，元数据标 `t_cta_est:true` 不当精确值；③结构比对**分两栏**：平台规格栏（官方规格）与我方从严栏，只对前者判 oracle pass/fail——用自家严线判 oracle 会大面积假红；④新增第四层**不可达性比对**：同置无网/低速/低端机环境测首屏出现时间/白屏/卡死（真实广告竞争力大半在弱网中端机启动，语料自包含程度可直接量化，机检硬判据）。⑤「不要用 qacore 全绿当 oracle 比对通过条件」：比对是逐维度对标+差分报告，非整体判合格。

### 6.4 吸引力指标

①时序分位（6.3 区间判据，同一 harness 测 oracle 与我方产物取相对位置——唯一诚实做法，绝对行业数字不可得）；②**QCTR 结构代理**（采信 MM-B 前稿：QClicks=总点击−(hasty+proximity+auto+early)，定义来自 Unity Ad Quality 官方 glossary，docs.unity.com/en-us/grow/ad-quality/ux-patterns 及 glossary，来源：MM-B 前稿，本次未独立复核，限定：阈值表是坏 UX 打标线非好表现标杆且无 playable 列）——每个分量（点击坐标/距首帧时延/5 秒返回）均可在 Playwright 本地测，空打脚本 auto-click 天然爆表，直接接通反作弊红线；必须在「人类式点击序列」策略下测；③首屏结构指标（CTA 首帧可见率/祈使指令/手势提示——前稿实测 5/5，n=5 初步值，M0 在 21 条上全量复核后定稿）；④**盲评抽检**：同运行器+同策略录定长屏，混排、去标识、随机左右位、二元通过+三档严重度、判官版本冻结 sha256；只登记不设门（盲评是软判据，VLM 不单独当门，本群 video 线 CLIP 代理分教训，基线§3.5）；仅对指标已判偏离条目做。⑤oracle 分位跑出后，复核三个无出处内部参数：MAX_DURATION_SEC=30、durationBudgetSec.target、difficulty.targetLevel（grep 全仓无消费无出处，M3 有据则改无据则登记）。

### 6.5 版权红线（owner 签字后生效）

21/21 语料著作权在广告主/代理商、无开源许可：①库只存特征向量+派生指标+缩略截图+人工标注，不存源包入 git；②源包本机隔离目录、不外发、不进交付包；③**硬隔离：oracle 源包严禁喂入 LLM 生成上下文（间接复制）**，工具层强制 oracle 目录只读 + assetkit 输入白名单排除；④GPL-2.0 件不参考；⑤录屏入库与 APK 提取挂起待 owner 法务口径；⑥对外只发布派生特征不发布原文件。

## 八、测试与质量策略（策略级；详细测试文档 stage4 另出）

**总纲：三解耦 + 统计契约**（采信 MM-C）。现有 48 包差分证明的只是极窄口径的等价性（N=1×48 的等价性数据，非稳定性数据；96=2 腿×48 格，同格仅 1 次）——升级线必须把证明拆成：①**输入解耦**（holdout 未见过才证明泛化，防 memorization）；②**判官解耦**（判官不与产物同谋）；③**留档解耦**（门禁输出可被第三方独立复算，.gitignore 白名单+只追加，基线§六.1/§六.6 两次事故为鉴）。

**判官三档驱动，同一判据、同一报告结构**：档 1 白盒钩子（`__PF_QC__`，仅限自家产物）；档 2 探针注入（只读探针+判官侧策略输入：网格扫描/随机点按/扫掠——**主推**，唯一同时满足「面向任意第三方游戏」与「判官解耦」）；档 3 纯黑盒兜底（随机输入+像素流，证据强度最低档显式落盘）。报告一等公民字段 `judge_drive_tier:1|2|3`，**分档统计严禁合并**。外部输入严禁注入白盒钩子（我替它声明它可玩 = 判官同谋，报表全绿实际全假——现有 CHK07 对第三方结构性必挂，checks.ts:190-192，这不是缺陷是白盒边界）。

**DQC/EBR 分工铁律：凡能机检的绝不交给 LLM**（LLM 判官方差无法做回归门禁、偏置在主观题最强、无法证伪）。DQC 确定性机检：L0/L1/L2/L3a 全部硬判据（定位到 CHK 或文件行）；EBR 体验盲评：二元通过+三档严重度（否决五分制——相邻档区分度差，实际只有 3 档），评分者间一致性独立测 3 次报告（无自测信度的标尺不采用）。

**反作弊三红线（全机检）**：①假可玩→CHK11 帧间动态性+输入响应因果性（现有 CHK05 单截图+高方差静态海报可骗过——真实可复现作弊面；MUT-03「结束页不可达」补齐，恰是假可玩家族缺失的那个变异）；②幻觉功能→功能清单回归（产物机制集合 ⊆ 输入抽取清单且逐项有实现证据；宁漏检不误杀）；③超时降级→TIMEOUT 第三态，单列不并入 pass/fail。**变异覆盖硬门禁：无恰命中变异样本的 CHK 一律「未证明有效」不计入 L1。**

**统计口径**：分桶 (输入形态×机制族×渠道——渠道必须单列，maxBytes 3–5MB、maxFiles 1–512 差两个数量级)；题级与试次级双报；N≥5（尾部形状非置信区间，报点估计需声明）；失败分类学 8 类 F1 INPUT_UNPARSABLE/F2 MECHANISM_MISS/F3 BUILD_FAILED/F4 COMPLIANT_FAIL(CHK01-06)/F5 PLAYABILITY_FAIL(CHK07/11)/F6 HALLUCINATED/F7 TIMEOUT/F8 CHANNEL_ONLY，附 stage 字段映射认知层阶段（intake/understand/synth/qc/appeal）；F4 中「判官无法判定」单列（假绿主要藏身处）。

**holdout 与红路**：物理隔离非约定隔离（独立凭据后端仓，seal 登记提交号+sha256，解封需 owner 动作；peidian/zcode 两前车之鉴，基线§5.3）；`first_seen_at` 字段+去重扫描（防「偷偷用过了」——若 holdout 输入产物带其特征且 first_seen_at 早于 seal 即判泄漏整轮作废）；判官 prompt/模型/参数跑前冻结登记 sha256，针对 holdout 表现的任何 prompt 修改作废该轮重跑；红路坏输入 ≥20%，错误接受=0 红线、错误拒绝只报不设门（设门会诱发坏输入构成失真）。
