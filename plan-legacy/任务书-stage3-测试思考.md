# 任务书 stage3：测试规划思考（五代理独立并行，只输出思考过程）

> 版本 v1.0（2026-10-03）。上游：`_playable_plan\最终规划文档.md`（权威，已定稿）。
> 你是五位测试规划思考代理之一，为规划文档设计实现测试。产出是**思考轨迹**，不是测试文档。

## 输入（必读）

1. `_playable_plan\最终规划文档.md`（规划的 DoD、类型全集、合规矩阵、架构、里程碑是你的测试对象）
2. `_baseline_inventory\项目真实能力基线总文.md`（现有评测文化：红路 fail-closed、独立复核、退出码语义 0 绿/1 红/2 用法错——测试设计要与之咬合）

## 输出要求（同 stage1 文体）

写「怎么想的」：测试怎么分层、判据怎么定、为什么、坑在哪、开放问题。每份 2000–5000 字，中文。纪律同 stage1（独立：不读 stage3-thinking 下其他文件与最终测试文档；诚实；只读现仓）。

## 两类测试（规划文档与最终测试文档必须覆盖）

- **开发者可见测试**：日常开发跑的门禁（单元/集成/E2E/构建），快速反馈，能定位失败；
- **holdout 测试**：隔离验收——验收集不进开发视野、判官与开发者分离、最终放行的唯一依据。

## 五个视角（与派遣一一对应）

### 视角T1 GLM-A：测试总架构（输出 `stage3-thinking\testthinking-T1-测试总架构.md`）
测试金字塔怎么切（单元/集成/E2E/批跑/holdout 各层对象与耗时预算）；门禁与退出码语义怎么统一；与现有 eval 文化（独立复核器、红路 fail-closed、评测输出无时间戳可复跑）怎么衔接；CI 化与本地跑的取舍；对「规划文档每个承诺至少对应一个测试」的覆盖性怎么检验。

### 视角T2 GLM-B：交付质量测试（输出 `stage3-thinking\testthinking-T2-交付质量.md`）
DoD 每一级（L0 构建→L3 吸引人）逐级怎么测：可玩性验证（真实交互/胜负判定怎么自动判定——无头浏览器？事件流断言？）；平台合规自动门（静态+运行时分层）；吸引力比对测试（与 oracle 的结构/行为/体验三层比对怎么落地、盲评协议怎么设计、判官 prompt 怎么防漂移）。

### 视角T3 MM-A：输入集与 oracle 库测试（输出 `stage3-thinking\testthinking-T3-输入集与oracle库.md`）
真实游戏输入集的建设与元数据规范怎么测（来源可追溯、形态可执行、类型覆盖矩阵达标）；oracle 样本库的校验测试（样本完整性、元数据齐全、去重）；版权与合规注意怎么变成流程测试；输入集版本化与冻结机制（防中途换题）。

### 视角T4 MM-B：稳定性与统计测试（输出 `stage3-thinking\testthinking-T4-稳定性与统计.md`）
「任意输入稳定产出」的统计方案：N 轮批跑设计、按类型分桶的成功率/方差指标、显著性怎么算（多少样本才够说稳定）；回归测试（同输入重跑产物漂移度）；fuzz/坏输入测试（畸形描述、空输入、超大输入、非游戏输入必须被拒——红路）；失败分类学与可诊断性要求（每次失败必须归因到可修的模块）。

### 视角T5 MM-C：holdout 设计（输出 `stage3-thinking\testthinking-T5-holdout设计.md`）
holdout 集怎么建（从类型全集抽样但冻结、不进开发视野的物理/流程隔离）；验收判据与放行条件（多少类型×多少样本×什么指标=通过）；判官独立性协议（谁跑判官、开发者能看到什么/看不到什么）；反作弊机检（假可玩、幻觉功能、超时降级充数的拦截测试）；holdout 轮换与泄密处置。
